# D5-02a Representative Mirror Evidence

This document is intentionally duplicated byte-for-byte in a second fixture under a different filename. The duplication represents a realistic research condition in which two distinct URLs, mirrors, export paths, or document identities expose the same cleaned evidence body. The benchmark uses the two identities as separate admitted sources so WorkSpace can measure whether exact-body suppression removes redundant synthesis context without changing the underlying evidence meaning.

The governing rule is deliberately narrow. Exact-body suppression may act only when the complete cleaned UTF-8 evidence body of a later source is identical to a body that was already supplied in full to synthesis. The implementation must not use semantic similarity, embeddings, fuzzy matching, paraphrase detection, language-model judgment, or source-title heuristics. A source that was truncated, skipped by the hard context budget, empty, or otherwise not supplied in full must never establish a duplicate canonical that can suppress a later copy.

Source provenance remains authoritative even when a duplicate body is omitted from the synthesis prompt. The duplicate source identity may remain in metadata for audit and traceability, but a source whose evidence body was not supplied to synthesis cannot be used as citation authority for that synthesis result. Two mirrors of the same evidence therefore cannot be counted as two independent corroborating sources merely because they have different source IDs, filenames, or URLs.

The optimization is subordinate to WorkSpace correctness gates. A reduction in rendered characters is not by itself a production benefit, and character reduction must not be mislabeled as token reduction. Promotion requires measured model-token efficiency on the same fixed task scope, no decrease in Verified Task Success, no decrease in First-Pass Verified Success, no decrease in verified task count, no decrease in Evidence Coverage, and no loss of required validator passes. Context precision and recall diagnostics must keep their existing definitions even when duplicate suppression changes those diagnostics.

The security boundary is unchanged. Duplicate detection grants no network, file, tool, cache, model, write, or authorization capability. Raw evidence bodies and their SHA-256 values are not required in published benchmark receipts. The benchmark may prove equality from the controlled local fixture corpus, while publishable artifacts remain metadata-only. Public Internet access is not required for this test, and no confidential data should leave the local benchmark trust domain.

A positive engineering decision requires an actual measured benefit. If the candidate produces zero token reduction, worsens token cost, loses verified quality, loses a required validator, changes the fixed task scope, changes the fixture corpus, or cannot prove that the baseline and candidate configurations differ only in the intended benchmark dimension, D5-02a must remain disabled by default. A verified NO-GO is a valid result and should not be rerun repeatedly without changing the candidate or the representative workload.
